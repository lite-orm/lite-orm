# Issue Tracker: GitHub

Specifications and implementation tickets for this repository live in GitHub Issues at `kervix/kervix`. Use the `gh` CLI from this clone so the repository is inferred from `origin`.

## Conventions

- Publish an agreed specification as one issue with explicit acceptance criteria.
- Split multi-step delivery into dependency-aware tracer-bullet issues rather than a permanent checklist document.
- Link implementation pull requests to their owning issue.
- Record investigation evidence and resolved decisions in issue comments.
- Close completed tickets; promote only durable behavior into contracts, ADRs, `CONTEXT.md`, or `docs/project/roadmap.md`.
- Pull requests are delivery artifacts, not a feature-request or triage surface.

When a skill says to publish to the issue tracker, create or update a GitHub issue. When it says to fetch the relevant ticket, read the issue body, labels, dependency links, and comments before acting.
