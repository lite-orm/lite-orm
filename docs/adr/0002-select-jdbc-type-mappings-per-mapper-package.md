# Keep standard JDBC routing fixed in Core

LiteORM uses one fixed Core `TypeHandlerManager` instead of package-selected mappings or database-specific type artifacts. Generated code supplies Java parameter and result target types; at runtime the manager combines that information with optional placeholder `jdbcType` declarations or live `ResultSetMetaData`, while generated code still performs direct record construction and JavaBean setters. Exceptional writes use a parameter-level `ParameterBinder`, and exceptional reads use a method-level `RowMapper`. This keeps ordinary use configuration-free and database-independent without schema discovery, reflection-based object construction, classpath scanning, `ServiceLoader`, or a mutable global registry.
